# Troubleshooting

- **`python` is missing:** install maintained CPython 3.11–3.14 and reopen PowerShell. `scripts/setup.ps1` also searches the standard per-user installation directory.
- **PowerShell blocks npm.ps1:** use `npm.cmd`, as all documented commands do.
- **Browser readiness fails:** rerun setup with network access so the pinned Remotion tooling can install its compatible Chrome Headless Shell, then rerun `techshort doctor` before working offline.
- **PDF says OCR required:** V1 intentionally does not guess text from scans. Provide a text-based PDF, Markdown, or text version.
- **PDF extraction is rejected as oversized:** convert it to a smaller text-based source or split it; techshort caps both input size and cumulative extracted output.
- **Codex provider unavailable:** install/authenticate the current Codex CLI or use `--provider fixture` / `--provider manual`. No API key is required for the offline workflow.
- **Codex returns schema errors:** update the CLI, run `codex login status`, and retry once. techshort permits only one bounded schema-repair attempt.
- **Narration import is rejected:** confirm FFmpeg/FFprobe is installed and the file contains a valid positive-duration audio stream; a renamed or malformed file is not accepted.
- **Kokoro says its model cache is missing:** while online, run `techshort audio setup --provider kokoro --yes` once from the repository root. Normal setup intentionally does not download the model. The cache is Git-ignored and should not appear in project exports.
- **Kokoro tries to load a model while offline:** synthesis never permits remote models. The cache is absent, incomplete, or no longer matches the pinned runtime expectation; reconnect only for the explicit `setup` action, then retry synthesis offline. Do not edit the helper to permit remote models during synthesis.
- **Kokoro setup reports unexpected identity:** the supported runtime is model `onnx-community/Kokoro-82M-v1.0-ONNX`, revision `1939ad2a8e416c0acfeecc08a694d14ef25f2231`, `q8`, CPU. Stop and inspect the lockfile/runtime if setup reports something else. An unexpected aggregate cache hash may reflect a local change and requires review; it is not repaired by hand-editing metadata.
- **Kokoro input is rejected:** use exact JSON fields `schemaVersion`, `voice`, `speed`, and `segments`; each segment permits only `segmentId` and single-line `text`. Choose a voice returned by `node renderer/scripts/kokoro-local.mjs voices`, keep speed from `0.75` to `1.5`, and stay within 100 segments and 128 KiB total text.
- **No local synthetic voices are listed:** `techshort audio voices` lists the reviewed Kokoro allowlist by default; run it with `--provider sapi` for enabled Windows System.Speech voices. Neither path is a cloud fallback or voice-cloning feature.
- **Local synthesis is blocked:** approve every current script segment first. For Kokoro, choose an allowlisted voice and keep `--speed` from `0.75` to `1.5`; for `--provider sapi`, keep `--rate` from `-10` to `10` and `--volume` from `1` to `100`. Regenerating the script makes an earlier synthesis receipt and timing stale.
- **Synthetic narration blocks rights:** this is the safe default. The Kokoro model/runtime are Apache-2.0, but generated voice/output rights are still `unknown`; Windows System.Speech output has the same separate-review requirement. Review the selected voice and output terms, then record accurate rights status and concrete license/attribution when required. Do not use a more permissive label merely to clear QA.
- **Sound design cannot be generated:** approve the current script and regenerate its current retention plan. The plan must contain allowlisted sound cues. `--preset` accepts only `subtle` or `present`.
- **Preview says narration is required:** import reviewed narration, or explicitly choose caption-led output with `techshort audio mode <slug> silent-reviewed`. Missing audio never switches modes automatically.
- **Storyboard approval says a cover is missing:** run `techshort cover generate <slug>`, inspect all three directions, then run `techshort cover select <slug> <candidate-id>` before approving the storyboard.
- **Pacing or safe-zone changes made approvals stale:** this is intentional. Reinspect the storyboard and cover, then regenerate the preview, contact sheet, scene stills, captions if affected, and QA before repeating final approval.
- **Retention QA says the schedule is missing or stale:** regenerate the script with the selected provider, review the narrative/beat/retention artifacts, then reapprove the script. Do not hand-edit version IDs or copy a plan from another script.
- **Cold-open or cadence QA fails:** keep the first honest beat at five seconds or less, declare the first attention event by two seconds, and keep every planned gap--including the last one--at five seconds or less. Re-hooks must advance an approved mechanism or evidence payoff rather than use engagement bait.
- **Creative QA reports a warning:** inspect `renders/<preview-or-final>/creative-quality.json`, the contact sheet, and the representative still beside every storyboard scene. The aggregate score is advisory, but hard cover/provenance/accessibility/media failures still block export.
- **Caption or motion accessibility fails:** lengthen or split overlapping/too-fast cues and remove strobe or rapid flash directions. The motion check is not full pixel-luminance analysis, so also watch the exact rendered preview before approval.
- **Permissively licensed narration is rejected:** provide concrete creator and license metadata (plus URL/attribution when required), or correct the asset in the rights reviewer before approval.
- **Cover experiment creation is blocked:** create it only from a current approved export with current final media, reviewed cover candidates, and exported captions. The experiment needs two or three candidates and does not replace normal cover review.
- **Observation import is rejected:** start with `experiment metrics-template`, replace every `REQUIRED_` placeholder, and enter actual cumulative post-level aggregates. Use timezone-aware timestamps, one content-level publication reference per variant, nondecreasing totals, and no unknown or viewer-level fields.
- **Experiment analysis says windows are not comparable:** collect snapshots at similar elapsed post ages. Do not alter timestamps to force a comparison; timing and audience differences are real uncertainty.
- **Experiment result remains `collect-more-data`:** one or more variants may be below the configured view threshold, missing the primary count, using unequal windows, or have overlapping intervals. Aggregate-only views, watch time, and engagement metrics deliberately cannot authorize a winner.
- **Recommendation cannot be approved or applied:** only a current conclusive recommendation can be approved. New observations stale older recommendations. Approval changes nothing; run `apply-recommendation` separately, and expect a changed cover to invalidate storyboard, rights, and final review.
- **TikTok upload diagnostics report missing credentials:** create and approve a TikTok developer app, authorize the intended account with the `video.upload` scope, and inject `TECHSHORT_TIKTOK_ACCESS_TOKEN` plus `TECHSHORT_TIKTOK_OPEN_ID` from the same OAuth token response into the current process environment. Keep `.env.example` blank. techshort never stores or logs these values and does not accept cookies or browser sessions.
- **Publication request or package is blocked:** approve the exact experiment and variant, preserve their media/cover hashes, export current SRT/VTT captions, and use only project-contained artifact paths. Grant consent only after inspecting the pending package.
- **TikTok draft preflight is blocked:** use the granted package manifest, preserve every package byte, and confirm the project still has the same approved final export, experiment, variant, evidence, claims, limitation, rights, media, captions, and cover. Preflight is local and never contacts TikTok.
- **TikTok API consent is rejected:** package consent is not API-transfer consent. Use the exact confirmation `I explicitly authorize transfer of this exact package to the identified TikTok account as a draft.` and verify the account label and OAuth OpenID identify the intended account. A package or account change requires a new intent and decision.
- **TikTok upload is `ambiguous`:** do not rerun it. A timeout, disconnect, or malformed response may have occurred after TikTok accepted bytes. techshort deliberately performs no blind retry. If the receipt retained a publish ID, poll that same attempt; otherwise inspect the intended TikTok account. A separate transfer requires a newly prepared and approved immutable package, intent, and consent.
- **TikTok rejects the video size:** the conservative V1 client accepts one MP4 chunk no larger than 64,000,000 bytes. Use the existing manual package workflow for larger reviewed videos.
- **TikTok draft has no selected cover or post copy:** the official draft upload transfers only the MP4. Burned-in captions remain, but the package's separate cover PNG, SRT/VTT, post copy, hashtags, alt text, and checklist remain local. Select the reviewed cover and finish metadata manually in TikTok.
- **A granted package or successful transfer did not post:** package consent permits only the selected manual action, and the API path creates only a TikTok inbox draft. Complete and publish it yourself in the platform composer. techshort never uses Direct Post, schedules, automates a browser, or claims a public post occurred.
- **TikTok draft status cannot be polled:** poll only a persisted nonterminal intent with `publication upload-status <slug> <experiment-id> <intent-id> --network`. Failed, complete, and cancelled attempts are terminal. An ambiguous attempt can be polled only when it retained a provider publish ID; polling never re-uploads the video. All records remain append-only.
- **Export blocked:** run `techshort status <slug> --json`, repair stale/failed artifacts, rerun QA, watch the preview, then approve the final gate.
- **Narration differs from captions:** correct the approved script, regenerate synthetic narration (or replace an imported recording), regenerate captions, and review again. Audio changes invalidate final approval.
